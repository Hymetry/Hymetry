Privacy settings

Recording privacy

We take privacy seriously. By default, Hymetry detects and masks common sensitive patterns (like emails, passwords, phone numbers, and credit-card-like numbers) on our servers as soon as event data arrives from the client before it's written to persistent storage. For example, if a user types email@example.com, we store email@*******.com.

Control what's captured

You can easily decide what we record by adding these CSS classes to your markup:

Class CSS class to add to an element in the tracked application Effect How the class changes session recording capture
.rr-block The element and its children are not recorded. During replay, a placeholder with the same dimensions is shown.
.rr-ignore Input events inside this element are not recorded (typed characters, changes, selections).
.rr-mask All text content of this element and its descendants is replaced with masking characters in the recording and replay.

Examples

<!-- Block an entire widget -->
<div class="rr-block"> ... </div>

<!-- Ignore keystrokes in a field -->
<input class="rr-ignore" type="text" placeholder="Type here" />

<!-- Mask text content -->
<div class="rr-mask">
  <span>Order #847392</span>
</div>

Good practices

  • Use .rr-block for auth widgets, payment iframes, third-party chats/CRMs, or any component you don't control.
  • Prefer .rr-ignore on free-text inputs where the UI context is useful but keystrokes are not.
  • Use .rr-mask to hide labels, IDs, or snippets that might occasionally contain sensitive data.
  • Avoid placing PII in HTML attributes (e.g., aria-label, data-*). If unavoidable, block the element with .rr-block.
